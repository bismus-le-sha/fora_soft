# Handoff: Видеочат-комната (video-chat-room)

## Overview

Лёгкий групповой видеозвонок в браузере на 4 участника с текстовым чатом и без регистрации:
открыл ссылку → представился → говоришь. Пакет описывает UI/UX всех экранов и состояний из
дизайн-PRD `prd-video-chat-room` (§6 флоу, §8 экраны, §9 состояния).

Утверждённая композиция экрана комнаты — **вариант 1c «Говорящий крупно»**: активный участник
занимает основную сцену, остальные — вертикальной лентой справа, управление медиа перенесено
в верхнюю плашку.

## About the Design Files

Файлы в `prototypes/` — это **дизайн-референсы, сделанные в HTML** (прототипы, показывающие
внешний вид и поведение), а не продакшн-код для копирования. Задача — **воспроизвести эти
дизайны в целевой кодовой базе** её собственными средствами (React/Vue/Svelte + ваша система
стилей), следуя её паттернам. Если кодовой базы ещё нет — выбрать подходящий стек и реализовать
дизайн там. HTML-разметку прототипа можно и нужно читать как источник точных значений
(цвета, отступы, радиусы, тайминги), но структуру компонентов стоит выстроить по правилам
целевого проекта.

Прототипы используют внутренний рантайм (`support.js`, теги `<x-dc>`, `<sc-if>`, `<sc-for>`) —
это только среда просмотра, переносить её в продакшн не нужно. Достаточно открыть
`Видеочат - прототип.dc.html` в браузере: работает вся навигация.

## Fidelity

**High-fidelity (hifi).** Финальные цвета, типографика, отступы, радиусы, тайминги анимаций и
копирайт. Реализовать pixel-perfect: все значения перечислены ниже и присутствуют в разметке
прототипа.

## Layout constants

- Только десктоп, корректная работа от **1024px** ширины; мобильная адаптация вне скоупа.
- Язык интерфейса — только русский.
- Ничего не сохраняется между перезагрузками (имя вводится заново).
- Все участники равноправны: у создателя комнаты нет визуальных отличий.
- Базовая сетка: внешние отступы контента `18px`, внутренние отступы плашек `20px`,
  зазор между плитками `12–14px`.

## Interactions & Behavior

**Флоу A (создание):** стартовый экран → валидация имени в реальном времени → «Создать комнату» →
экран подготовки к доступу → комната из одного участника с акцентом на «Скопировать ссылку».

**Флоу B (вход по ссылке):** экран ввода имени (та же валидация) → подготовка к доступу →
комната с уже присутствующими участниками. Вошедший видит всю историю чата;
своё системное «вы присоединились» ему не показывается, остальные видят «N присоединился».

**Флоу C (медиа):** микрофон и камера включены по умолчанию; переключение — один клик в верхней
плашке; статус мгновенно отражается на своей плитке (иконка `#C24A22`, заглушка вместо видео)
и на плитках у остальных.

**Флоу D (чат):** панель закрыта по умолчанию; при закрытой панели новые сообщения инкрементируют
бейдж непрочитанных, открытие панели сбрасывает его в 0; отправка — Enter или кнопка;
автопрокрутка вниз; системные события визуально отделены.

**Флоу E (выход):** кнопка «Выйти» → модальное подтверждение → возврат на стартовый экран.
Закрытие вкладки эквивалентно выходу (без отдельного экрана).

**Валидация имени (реальное время):** `trim()`; пусто → невалидно; > 30 символов → невалидно;
разрешены только `A-Za-zА-Яа-яЁё0-9`, пробел, `_`, `.`, `-`. Кнопка отправки заблокирована
до валидного значения; после первой неудачной попытки подсказка меняется на явную.

**Анимации (motion — средний, сдержанный уровень):**
| Момент | Анимация |
|---|---|
| Появление плитки участника | `tileIn .45s cubic-bezier(.2,.8,.2,1)`: `opacity 0→1`, `scale(.965)→1`, `translateY(8px)→0` |
| Исчезновение плитки | обратная, 300ms, та же кривая |
| Появление экрана / карточки | `fadeUp .4–.5s cubic-bezier(.2,.8,.2,1)` (`translateY(10px)→0`) |
| Новое сообщение | `msgIn .3s` (`translateY(6px)→0`) |
| Открытие/закрытие панели чата | `width .32s cubic-bezier(.2,.8,.2,1)` |
| Переключение микрофона/камеры | `background .18s ease, color .18s ease` |
| Тост копирования | `opacity .2s`, `translateY .24s`, автоскрытие 2200ms |
| Ожидание (точки) | `dotPulse` 1.1–1.6s, `opacity .18↔1`, задержки 0/.2s/.4s |
| Кольцо запроса доступа | `ringPulse` 2.2s, `scale(1)→1.9`, `opacity .5→0` |
| Hover кнопок | `transform: translateY(-1px)` `.14s ease`; рамки `.16s ease` |

**Responsive:** от 1024px. Сцена всегда 16:9 и центрирована в своём боксе; лента справа
`292px`, при открытой панели чата (`344px`) — `208px`, чтобы главный кадр оставался заметно
крупнее превью. Ниже 1280px допустимо уменьшить ленту до 200px.

## State Management

```
screen: 'entry' | 'perm' | 'room'
mode: 'create' | 'join'          // какой из двух входных экранов
name: string, touched: boolean   // ввод имени и признак попытки
micOn, camOn: boolean            // свои устройства
denied: boolean                  // браузер отказал в доступе
participants: [{ id, name, camOn, micOn, speaking }]  // до 4 вместе с собой
activeSpeakerId                  // кто на сцене: говорящий, иначе первый другой, иначе вы
chatOpen: boolean, tab: 'chat' | 'people'
unread: number                   // растёт при закрытой панели, сбрасывается при открытии
draft: string
messages: [{ author?, text, mine?, time?, system? }]
toast: boolean                   // подтверждение копирования (2.2s)
exiting: boolean                 // модальное подтверждение выхода
seconds: number                  // таймер звонка, тик 1s
```

Переходы: `submitName` (валидно) → `room` с mic/cam off; восстановление звонка →
независимый выбор mic/cam → `perm` только для выбранных устройств → `room` (`denied` при отказе);
событие «участник вошёл/вышел» → изменение `participants` + системное сообщение;
`toggleChat` → сброс `unread`; `doExit` → сброс всего состояния и `screen = 'entry'`.

Данные: комната по коду из URL (`/r/RM-4F2A`), сигналинг и медиа — по техническому PRD
(`prd-video-chat-room.md`). Прототип имитирует вход участников таймерами
(2.6s / 5.2s / 3.4s) — в продакшне это реальные события.
